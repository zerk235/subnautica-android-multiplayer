# Демонтаж деталей базы: исправление 0.3.2

Входит в установщик 0.3.2. В игровом тесте на двух телефонах прошли два полных
цикла постройки и удаления нового отдельного прямого отсека. На госте журнал
подтвердил готовность API и удаление каждой пустой новой базы с `verified=1`.

На двух телефонах воспроизведён сценарий: полностью построенный отдельный прямой
отсек появляется у гостя, после полного разбора у хоста остаётся у гостя. Сетевое
сообщение удаления приходит, но применение блокируется последовательно в двух местах.

Первое: у завершённой базы, созданной в текущей сессии, нативный `isPlaced` может
оставаться ложным. Поиск цели принимал только базы с этим флагом. Теперь для такой
базы требуется ранее подтверждённая запись её создания, точный идентификатор,
валидные массивы геометрии и совпадение сохранённой системы координат. Предпросмотры,
неоднозначные идентификаторы и активное размещение остаются заблокированы.

Повторный живой тест подтвердил, что поиск новой базы проходит. Следующая строка
лога выявила второе препятствие: `corridor removal API unavailable`. Обработчик
пытался найти `Base.IsEmpty()` без параметров. Метаданные поддерживаемой версии игры
содержат `Base.IsEmpty(BaseGhost ignoreGhost)`. Из-за обязательности этого метода
не включался весь обработчик демонтажа, включая удаление деталей существующей базы.

Исправлены поиск метода по числу и типу параметра и ABI вызова. При удалённом
демонтаже, который не создаёт локальный ресурсный призрак, передаётся `null` в
`ignoreGhost`. Диагностика разрешения методов теперь показывает готовность каждого
компонента. `test_base_removal_api` включает настоящий код разрешения методов и
проверяет эту сигнатуру, аргумент, отказ при отсутствующем методе и зависимостях.
`test_single_cell_removal` проверяет настоящий обработчик удаления: последнюю
деталь новой базы, комнаты и фундаменты, соседние детали, идентичность, замену
детали в той же ячейке, исключения и чтение результата после записи.

Эти проверки и `test_base_target_lookup` прошли на обоих тестовых телефонах.
После двух успешных игровых циклов отдельного отсека остаётся повторить проверку
с последним фундаментом и всеми вариантами комнат. Старые оставшиеся детали не
проверяют сценарий создания новой базы в текущей сессии.
