# Занятое место в «Мотыльке»

Пользователь выбрал временную блокировку занятого транспорта. Пустой «Мотылёк»
не закрепляется за владельцем: после выхода пилота его может занять другой игрок.

## Проверка перед входом

`vehicle_seat_guard.inc` перехватывает два виртуальных вызова **только класса
SeaMoth**: `OnHandClick` (слот 6) и `EnterVehicle` (слот 53). Общая таблица `Vehicle`,
прочие типы транспорта и оригинальные методы игры не переназначаются.
Перед записью проверяются номер слота, размер таблицы и исходный адрес функции;
неизвестный адрес не заменяется. Неинициализированная таблица повторно проверяется
после начала игрового обновления.

Вход отклоняется, если по точному сетевому идентификатору этого «Мотылька» есть свежая
поза другого пилота из общей сессии. Появляется сообщение «Мотылёк занят
напарником». Сбой вывода сообщения не разрешает вход в уже известное занятое
место. Если точный идентификатор прочитать не удалось, сохраняется штатная
работа игры: расстояние до соседней машины не используется вместо идентичности.

В этой версии `Vehicle.OnHandClick` вызывает `EnterVehicle` через виртуальный
слот 53 (`0x2b79b94..0x2b79b9c`) до операций посадки. Одна лишь замена
`SeaMoth.CanPilot` не является достаточной проверкой этого пути входа.

## Освобождение места и старые пакеты

`vehicle_occupancy.h` проверяет снимки, уже принятые существующим протоколом;
формат сетевых пакетов не изменён.

- Свежая поза транспорта другого активного пира удерживает место занятым.
- `STATE` и `VEHICLE` используют общий счётчик отправителя. Более новый `STATE`
  без флага пилотирования освобождает место; старый пакет с таким флагом не
  отменяет более новую посадку.
- При переходе пилота в другую машину учитывается его более новая поза
  транспорта, даже если снимок прежней машины ещё хранится в таблице.
- При выходе пира или истечении пяти секунд без свежей позы удержание снимается.
- Сравнение последовательностей учитывает переполнение 32-битного счётчика.

Это проверка уже полученного состояния занятого места. Одновременные попытки
посадки до доставки первой позы пилота пока не арбитрируются отдельной выдачей
кресла хостом. Этот сценарий нельзя объявлять проверенным эксклюзивным замком;
при необходимости он потребует отдельного запроса и подтверждения посадки.

## Проверки

На обоих телефонах отдельно от игры прошли:

- `test_vehicle_occupancy`: занятое и свободное место, другая машина, собственный
  пилот, выход и повторный вход, исчезновение пира, таймаут, смена машины,
  устаревшие пакеты, переполнение счётчика, неверный класс и время.
- `test_vehicle_seat_guard`: исполняется настоящий код перехватчиков с тестовым
  API игры; проверены оба запрета входа, восстановление оригинальных вызовов
  после выхода пилота, неизменность общего `Vehicle`, повторная установка,
  сбой сообщения и отказ менять неизвестный виртуальный слот.

Первая игровая сборка `9409dc83...` запустилась, но сообщила `click=0 enter=0`:
проверка перед записью не разрешила установку. Разбор текущего `libil2cpp.so`
показал расхождение с прежним сгенерированным заголовком `Il2CppClass_2`.
`SetupVTable` читает размер таблицы по `+0x12a` (`0x2560764`, `0x2560b14`),
а `+0x126` относится к числу событий. Начало таблицы при этом остаётся
`+0x138`, что подтверждается проходом по её элементам и виртуальным вызовом
`EnterVehicle` из `Vehicle.OnHandClick`.

Новый перехватчик использует проверенное смещение `+0x12a`. Изменение ограничено
проверкой посадки; существующие перехватчики других игровых методов не меняются.
В тесте прежнее поле `+0x126` намеренно имеет значение 1, а настоящий размер
стоит по `+0x12a`, чтобы повторить найденный на телефонах случай.

Исправленная нативная сборка: `7355e7d490aebee2a75c4b6e749eb0a1ff326002`, SHA-256
`18984fc16d9fd37de7a7581ae9d2b4dc9186c7c608f1ad1fa3cc45788de2904a`.
Исправленный тест перехватчиков повторно прошёл на обоих телефонах.

### Вылет после включения перехватчиков

Сборка `7355e7d4...` действительно включила оба перехватчика на обоих телефонах:
`click=1 enter=1 ready=1 vtable_count=95`. Однако на руте произошли повторные вылеты
в `Loading.Preload`: `SIGSEGV / SEGV_ACCERR`, запись по адресу `0x7ae2244cc4`,
`libil2cpp.so+0x25ed1d0`. По дизассемблеру это атомарная запись `casal w0,w1,[x2]`;
стек проходит через `il2cpp_object_new`.

Обнаружена ошибка общего `mem_patch_write`: после записи он безусловно запрашивал
`PROT_READ | PROT_EXEC`. Для страницы с таблицей класса, выделенной средой выполнения,
это убирает разрешение записи также у соседних данных класса/аллокатора. Позднейшая
инициализация других объектов может упасть без непосредственного вызова блокировки.

Исправление `mapped_patch.h` читает исходные права из `/proc/self/maps`. Если память
уже доступна для записи, права вообще не меняются. Для защищённой страницы запись
разрешается временно, затем восстанавливаются исходные права; новые права исполнения
не добавляются. Диапазон через разные отображения отклоняется до записи.

`test_mapped_patch` прошёл на обоих телефонах: после изменения указателя на той же
странице выполняется атомарная запись, как в аварийном стеке; проверены также
восстановление readonly-страницы, сохранение соседней writable-страницы и отказ для
недоступного/пересекающего отображения диапазона. Повторно прошли оба теста блокировки.
Сборка исправления: `ec4f06e0ec881ba0bf4b8fd66b0b7522ea21f370`, SHA-256 библиотеки
`9fda5fe63e5c899c0a6b00c9372c471e2dee2df2578b62a2a53d95513926f015`.
Исправление установлено на оба телефона поверх игры; хеши всех сохранений и ресурсных
APK не изменились. На обоих проверена установленная библиотека и включение обоих
перехватчиков (`ready=1`, таблица 95 слотов). Повторная проверка запуска сохранила
те же процессы, новых аварий для них нет. Игрок подтвердил загрузку обоих телефонов.
После загрузки PID не менялись (рут `27823`, нон-рут `18604`), роли host/guest,
authority/epoch и мир совпадают, `mod_match=1`; приём движения идёт в обе стороны
без отклонённых пакетов. Предыдущий вылет во время загрузки в этом проходе не повторился.
Посадка ещё требует отдельной проверки игроком; предыдущую сборку нельзя считать стабильной.

### Посадка в сетевую копию

Первая попытка после устранения вылета не заблокировала гостя. На госте журнал
зафиксировал `spawned visual SeaMoth` для хоста, затем `veh sky baseline` уже при
локальном пилотировании **того же GameObject** (`0x6d4e22cb80`). У созданного префаба
собственный локальный `UniqueIdentifier`, который не совпадает с GUID транспорта
хоста. Поиск только по этому локальному GUID пропускает занятое место.

Перехватчик теперь сначала сопоставляет точный GameObject с активной записью
`g_driven` и использует GUID этой записи; для обычного транспорта остаётся его
`UniqueIdentifier`. Координаты и близость не используются. После разрешения
идентичности прежняя проверка свежести, пилота и выхода обязательна. В журнал
добавлен результат попытки с источником `replica`/`native` и найденным пилотом.

Дополненный `test_vehicle_seat_guard` прошёл на обоих телефонах: реплика с другим
локальным GUID блокируется, посторонний объект и неактивная запись не блокируются,
явный выход пилота освобождает также ещё существующую реплику. Живая проверка
этого дополнения пока не выполнена.

Сборка с сопоставлением реплики: `6833fdcc5e0314976c5ed3a3671a381b3abbd26a`,
SHA-256 библиотеки `b00abb38ec12da4c473a466e6e2e9ea325d224ee88d38dedbb7d090bd4ed71b6`.
Она установлена на оба телефона; свежие копии содержат 91 файл миров на руте
и 103 на нон-руте. Хеши сохранений и ресурсов после обновления не изменились.
Установленная библиотека проверена по SHA-256 на обоих, оба перехватчика включены,
роли сохранены: рут — хост, нон-рут — гость.

Игрок подтвердил, что блокировка работает. На нон-руте зафиксированы три попытки
входа в сетевую копию: `source=replica pilot=9f073ed0` и три сообщения
`entry blocked ... path=hand-click`. Процессы обоих телефонов сохранились.
Вход после выхода пилота и обратное направление этой живой проверкой пока не подтверждены.

Для живой проверки нужны две стороны: первый игрок уже управляет общей машиной,
второй пытается войти и получает отказ; затем первый выходит, второй входит.
После этого роли пилотов меняются. Дополнительно следует проверить другую
пустую машину и освобождение места после отключения пилота. Сборка не объявляется
прошедшей эти игровые проверки на основании одних отдельных тестов.
