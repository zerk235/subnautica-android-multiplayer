# Сборка для разработчика

Установщик для Android находится на предварительной проверке; его сборка и ограничения описаны [отдельно](INSTALLER.md). Ниже — сборка нативной библиотеки и локальное создание **неподписанного** APK из собственной копии игры.

## Инструменты

- Python 3.10 или новее; дополнительных Python-пакетов не требуется.
- Android NDK; рабочий проект собирался с `26.1.10909125`.
- CMake 3.22+ и Ninja; локальная проверка экспорта использует CMake `4.0.2`.
- Для ARM-тестов — ADB и Android ARM64-телефон с разрешённой USB-отладкой. Root не требуется.
- Для последующей подписи — JDK и Android SDK build-tools. Ключи подписи в репозитории отсутствуют.

## Нативная библиотека

Из корня репозитория, если CMake и Ninja находятся в PATH:

```sh
python tools/build.py --ndk /path/to/android-ndk
```

Пример PowerShell с явно указанными инструментами:

```powershell
python tools/build.py --ndk 'C:\Android\Sdk\ndk\26.1.10909125' --cmake 'C:\Android\Sdk\cmake\4.0.2\bin\cmake.exe' --ninja 'C:\Android\Sdk\cmake\4.0.2\bin\ninja.exe'
```

Пути в примере замените своими. Вместо `--ndk` можно задать `ANDROID_NDK_HOME`.
Результат: `build/android/out/libsnmod.so` и `build/android/snmod_build_id.txt`.
Цель: `arm64-v8a`, Android API 29, C++17, Release. Требования самой игры к Android
проверяются отдельно; API сборки мода не является обещанием поддержки Android 10.

Скрипт включает `SNMOD_BASE_GEOMETRY_CAPTURE` и `SNMOD_BASE_GEOMETRY_APPLY` —
проверяемую ветку синхронизации базы с протоколом 23. CMake без этих флагов
соберёт другую ветку; не смешивайте такие библиотеки в одной сессии.

Идентификатор вычисляется по исходникам, зависимости и конфигурации демо,
с нормализацией CRLF/LF. Оба телефона должны использовать один и тот же артефакт.
`python tools/build.py --print-build-id` выводит идентификатор без сборки.

## Проверки

Проверки инструментов используют синтетические данные, не игру:

```sh
python -m unittest discover -s tests -p test_tools.py -v
```

C++ проверки запускаются на устройстве отдельно от Unity и не перезапускают игру:

```sh
python tools/run_android_tests.py --ndk /path/to/android-ndk --serial YOUR_ADB_SERIAL
```

ADB должен быть в PATH, либо передайте `--adb /path/to/adb`. Выборочно:

```sh
python tools/run_android_tests.py --ndk /path/to/android-ndk --serial YOUR_ADB_SERIAL --test test_world_context --test test_world_complete
```

Тесты пишут только свои исполняемые файлы и фикстуры в `/data/local/tmp`.
`test_world_complete` очищает свой выделенный каталог
`/data/local/tmp/snmod_world_complete_tests`; игровой каталог сохранений он не использует.
Это проверки логики мода, а не замена игрового теста готовой сборки на двух телефонах.

## Локальный патч APK

```sh
python tools/patch_apk.py --base /path/to/your/base.apk --library build/android/out/libsnmod.so --output build/apk/base.unsigned.apk
```

Скрипт сохраняет исходный Unity bootstrap как `libmain_orig.so`, устанавливает
мод как `libmain.so` и удаляет старые подписи. Исходный APK не меняется,
существующий выходной файл не перезаписывается. Выравнивание, подпись и установка
не выполняются автоматически. Реальный патч из этого экспорта ещё нужно проверить
в игре; синтетические тесты проверяют только упаковку.

### Подпись и split APK

Перед подписью выполните `zipalign` (включая выравнивание нативных библиотек для
16-КиБ страниц), затем подпишите своим приватным ключом через `apksigner` и
проверьте подпись. Пароли вводите интерактивно, не сохраняйте в скриптах.

Важное различие:

- **Обновление уже совместимо подписанной установки:** меняется и подписывается
  только небольшой базовый APK. Повторно обрабатывать гигабайтный пакет ресурсов
  не нужно, если установленные split APK уже подписаны тем же сертификатом.
- **Первая установка с другим сертификатом:** базовый и все split APK должны иметь
  совместимую подпись. Замена одного подписанного базового APK поверх оригинальной
  установки с другим сертификатом не сработает. Удобный безопасный сценарий первого
  развёртывания ещё входит в план демо.

Не удаляйте игру автоматически при конфликте подписи: это может удалить сохранения.
Публичное распространение патченного игрового APK или игровых ресурсов не входит
в эту схему. В релиз можно включать собственную библиотеку/инструменты после
проверки и с сохранением сторонних лицензий.
