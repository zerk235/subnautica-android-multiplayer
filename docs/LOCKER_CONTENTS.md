## Поведение

Поддерживается обычный напольный Locker (1504) в точной общей базе. При открытии
гостем запрашивается актуальное содержимое у выбранного хоста. Перенос между
личным инвентарём и шкафом перехватывается до штатного удаления из источника.
Хост проверяет номер состояния шкафа и резервирует конкретный ID предмета.
Гость выполняет перенос после разрешения и подтверждает его; хост применяет
операцию к своей копии, увеличивает ревизию и отправляет результат.

Повторные запросы имеют тот же номер операции. Чужой или устаревший запрос не
может завершить резервирование. Если два игрока пытаются забрать одну вещь,
второй запрос получает отказ и обновление содержимого. При отсутствии места
предмет остаётся в источнике. Замена одного предмета другим при заполненной
сетке и прямой перенос между двумя шкафами в этой версии не поддерживаются.

Передаются собственный ID и TechType предмета, а для восстановления — байты
штатного `ProtobufSerializer`. Состояние не восстанавливается только по названию
ресурса. Скрытая копия подобранного предмета в мире переиспользуется по точному
ID; предмет в личном инвентаре или другом контейнере не перезаписывается.
Загрузка и проверки игровых объектов выполняются только в игровом потоке.

Сообщения идут через упорядоченный канал WorldEvent, с проверкой сессии,
дроблением, контрольной суммой и ограничением очереди. Изменение адреса Wi-Fi
не считается завершением операции и не снимает резервирование само по себе.

## Незавершённый перенос

Перед удалённым переносом записывается локальный журнал с данными предмета в
`files/mod_log/locker_contents`. Пока разрешённая операция не подтверждена,
срок ожидания не отдаёт эту вещь другому игроку. При исключении повторные
переносы останавливаются. Журнал после аварийного завершения сохраняется;
его наличие блокирует автоматическое повторение операции при следующем запуске.

Это **не готовое автоматическое восстановление после сбоя процесса**. Такой
журнал требует разбора; его нельзя удалять для обхода блокировки. Журнал с
байтами предмета не включается в обычный диагностический ZIP. В ZIP остаются
сообщения об операции, ID и причина остановки. Сохранение гостевого личного
инвентаря остаётся отдельным ограничением многопользовательской демоверсии.

## Первая проверка

Использовать новый отдельный шкаф и обычные тестовые ресурсы.

1. Хост кладёт один титан; гость открывает шкаф и забирает его. У хоста титан
   исчезает из шкафа, на полу ничего не появляется.
2. Гость кладёт один кварц; хост открывает шкаф и забирает. Проверить число
   вещей до и после — дублирования и потери быть не должно.
3. Повторить переносы при уже открытом шкафе на обоих телефонах, затем
   попробовать одновременно забрать один общий предмет.
4. Проверить заполненный инвентарь, сохранение хостом и полный перезапуск.
5. Отдельно проверить заряд батареи/инструмента, состояние еды и разрыв сети.

Пункты этого списка являются планом приёмки, а не перечнем уже пройденных
игровых проверок. Предварительный релиз включает проверенные выше сценарии; он не означает
завершённую проверку всех пунктов или автоматическое восстановление после сбоя.
