# Копирование новых гостевых сохранений

Причина проверена по `github/main` (`41a3de9`, 0.3.11) и правам файлов
на нон-рут телефоне 15 ноября 2026.

В `e6dce0d` (0.3.9) восстановление стало учитывать владельца игры. Root-путь
выставляет владельца игры, группу внешних данных и `2770` для папок.
Путь Shizuku без root выставлял `777` для папок и `666` для файлов.
Игра могла пользоваться восстановленной копией, но папки без setgid не
передавали группу `ext_data_rw` новым вложенным файлам.

Затем нативный перенос мира создавал папки `770` и файлы `660`, принадлежащие
UID/GID самой игры. На проверенном госте закрылись новый слот, его скрытая
предыдущая копия и файл options. У ADB/Shizuku есть группа `ext_data_rw`,
но нет группы приложения и права менять владельца его файлов.
Запущенный Shizuku поэтому не мог завершить резервную копию.

## Исправление

- При восстановлении через Shizuku папки получают `2777`: сохраняются прежние
  разрешения и добавляется наследование группы для следующих сохранений.
  Проверяется и setgid, а не только младшие биты доступа.
- Уже закрытые файлы исправляет их владелец — код мода в процессе игры.
  Проверяется только фиксированное дерево `SavedGames`, в главном меню и
  после приёма мира. Чужие UID и ссылки не меняются; обход ограничен
  глубиной и числом объектов, файлы открываются через дескрипторы без
  следования символьным ссылкам.
- При группе `ext_data_rw` добавляется чтение/проход для группы. У файлов
  с приватной группой приложения добавляется только чтение (и проход для
  папок) для процесса копирования, поскольку без root нельзя сменить их GID.
  Новые права записи не добавляются. Доступ обычных приложений к
  `Android/data` продолжает ограничиваться Android.
- В ошибке копирования теперь есть относительный путь, UID, GID и режим.
  Недоступные файлы не исключаются из архива молча.

Ремонт меняет метаданные доступа, а не содержимое, названия или состав
сохранений. Для первого ремонта существующей закрытой папки требуется
обновить игру тем же ключом и один раз открыть её до главного меню.
Переустановка с удалением не требуется.

## Проверка

`test_save_backup_access` проверяет реальные файловые операции на Android:
содержимое и UID остаются прежними, повторный ремонт не меняет режимы,
новые права записи не появляются, ссылка не меняет посторонний файл.
Тест прошёл на обоих телефонах. В `SaveTests` добавлена проверка setgid
после восстановления. Результат живого ремонта и полной копии записывается
отдельно; успешная компиляция не считается успешной копией.

Для проверки ремонта подготовлена отдельная сборка поверх 0.3.11,
с протоколом 33 и без постоянной синхронизации рыб.

Живой ремонт проверен на нон-руте: `checked=82 changed=21 errors=0`.
После него ADB прочитал все 65 файлов. Shizuku от UID 2000 создал новый архив
и подтвердил совпадение с текущими мирами. ZIP экспортирован на флешку,
проверены SHA-256 архива и размер/хеш каждого файла. Ресурсный APK сохранил
прежний хеш; игра обновлена поверх установленной тем же ключом, без удаления.
`SaveTests` с новой проверкой setgid и `test_world_complete` также прошли.

При проверке рыб после обычного игрового сохранения вновь появились закрытые
файлы. Перед установкой визуальных копий повторный запуск игры до меню дал
`checked=83 changed=8 errors=0`; затем полностью проверены 66 файлов гостя.
После следующего сохранения семь файлов снова оказались недоступны ADB.
Копирование остановлено на ошибке, неполный архив не принят за резервную копию.

Это ограничение текущего ремонта: он исправляет уже созданные файлы при
подтверждённом состоянии главного меню и после сетевой записи мира, но не
предотвращает создание закрытых файлов обычным игровым сохранением. В этом
тесте выход из мира не привёл к ремонту до повторного запуска процесса.
Для окончательного решения нужен надёжный сигнал завершения игрового
сохранения/перехода в меню и подтверждение ремонта перед копированием.
